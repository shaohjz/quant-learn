# REQ-010: 研发/测试 Agent 失败自动降级接管机制

## 背景
今天多次出现子 agent 超时或中断，导致需求实现、Bug 修复和测试报告产出不稳定。虽然主 agent 可以手动接管，但每日自动闭环需要明确降级策略，避免任务卡死。

## 目标用户/场景
当需求 agent、研发 agent 或测试 agent 失败时，主 PM 需要知道失败原因、是否已产生文件、下一步谁接管，并能继续推进闭环。

## 需求描述
每日闭环中加入 agent 失败降级机制：
1. 每次启动子 agent 时记录任务到 `pm/daily/YYYY-MM-DD.md`。
2. 如果子 agent 失败/超时：
   - 检查它是否已写入需求/Bug/测试报告/代码。
   - 如果没有产出，主 PM 直接接管小任务，或将任务拆小后重新派发。
   - 在日报中记录失败角色、失败阶段、接管动作。
3. 对于测试 agent 失败：主 PM 至少执行基础 API/文件检查，并写最小测试报告。
4. 对于研发 agent 失败：主 PM 不盲目标完成，必须保留 `pending/in_progress` 或写 Bug。
5. 每日汇报必须包含“Agent 健康状态”。

## 数据来源
- 子 agent 完成/失败事件
- `pm/daily/YYYY-MM-DD.md`
- `git status`
- `pm/requirements/`
- `pm/bugs/`
- `pm/test_reports/`

## 验收标准
1. 子 agent 失败后不会导致需求/Bug 状态长时间停滞且无说明。
2. `pm/daily/YYYY-MM-DD.md` 记录失败和接管动作。
3. 测试 agent 失败时，至少生成一份基础测试报告或明确说明未测试原因。
4. 每日汇报包含 Agent 健康状态。
