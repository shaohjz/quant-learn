# REQ-009: PM需求去重与需求池分层看板

## 背景
PM/需求 agent 可能反复提出上一轮已存在的需求，导致需求池膨胀、研发不知道优先做什么。需要在生成新需求前进行去重，并在看板中区分新需求、开发中、测试中、已完成、阻塞。

## 目标用户/场景
主 PM 和研发 agent 每天需要快速判断：哪些需求是新增的，哪些已经完成，哪些被 Bug 阻塞，哪些应该优先开发。

## 需求描述
在 PM 流程中增加需求去重和分层看板：
1. 新增需求前读取全部 `REQ-*.md` 的标题、背景、验收标准。
2. 如果新想法与已有需求高度重合，不新建文件，只在已有需求中追加“补充说明”。
3. `pm/README.md` 增加分层区域：
   - 今日新增
   - 待开发 pending
   - 开发中 in_progress
   - 测试中 testing
   - 已完成 done
   - 阻塞 blocked
4. 每个需求增加“来源”字段：用户反馈/日志发现/PM主动优化/Bug衍生。
5. 每日汇报只展示新增或状态变化的需求，避免重复播报全部旧需求。

## 数据来源
- `pm/requirements/*.md`
- `pm/README.md`
- 当天用户反馈
- 当天日志/复盘报告

## 验收标准
1. 新需求生成前会读取已有 REQ 文件做去重。
2. 重复需求不会新建新的 REQ 编号。
3. `pm/README.md` 能按状态分层展示。
4. 每日汇报包含“今日新增/今日变化”，不再只复述旧需求。

## 优先级
P1
