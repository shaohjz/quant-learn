# QMT mini 账户长期零成交，双账户镜像未实际生效

## 描述

对比 2026-05-19 与 2026-05-26 复盘：sim 账户期间产生数十笔成交并发生明显浮亏(-1.86%)，但 QMT mini 90072426 账户连续多日均显示 0 笔成交、现金 10,000,000、总资产 10,000,000、+0.00%。预期双账户(sim 与 QMT mini)应保持镜像/同步执行以便对照验证策略，但实际 QMT 通道完全静默。需要排查：(1) QMT 自动下单链路是否被禁用或鉴权失败；(2) live_mirror 是否只回写 sim 库而未触达 QMT；(3) 日志/告警是否缺失导致 7 天无人察觉。该问题导致 REQ-034(双账户一致性诊断)与精准狙击策略验证完全失效。

## 根因

dry_run=True + sim-only routing + QMT client not running; old QMT broker only wrote fills, so no local audit trail existed when submits were skipped/dry-run/unfilled.

## 修复备注

BUG-013 completed by quant-learn-dev-agent-1 (2026-06-01 09:50).
Root cause verified: config.local.yaml broker.live.dry_run=True, global broker.mode=sim, QMT client not running, and last 7d sim/live_mirror had 24 fills while QMT submission/fill records were 0. Latest fusion_dispatch log also had qmt_dry_run=True.
Fix: broker/qmt_broker.py now records every QMT submit attempt into sim_orders (broker=qmt/qmt_dry_run), and QMT fill callback now writes existing sim_trades columns direction/broker_order_id instead of stale side/order_id. qmt_diagnostic.py was rewritten to diagnose config, xtquant/QMT process, submit-layer audit, fill callbacks, dispatch logs, and dry_run blockers.
Validation: python -m py_compile broker/qmt_broker.py scripts/qmt_diagnostic.py; python -m pytest tests/test_bug013_qmt_submission_audit.py -q (2 passed); python scripts/qmt_diagnostic.py --push-wecom with NOTIFIER_DRY_RUN=0 pushed the diagnosis to WeCom.
Next manual step before real QMT-mini trading: start/login QMT mini 90072426, then explicitly decide whether to set broker.live.dry_run=false. Real account 8890461376 remains hard-blocked.
