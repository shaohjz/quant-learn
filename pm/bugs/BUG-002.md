# BUG-002: scanner fallback 在 Windows GBK 输出下因 Emoji 打印崩溃

## 严重级别
S1

## 状态
verified

## 关联需求
无

## 发现来源
2026-05-25 今日日志：`output/market_scanner_runner.log`、`output/morning_scanner.log`。

## 现象
`scripts/scanner_with_fallback.py` 在主路径 `morning_scanner.py` 超时后，本应切换到 `scanner_lite.py` 降级扫描；但打印包含 Emoji 的提示时触发 `UnicodeEncodeError: 'gbk' codec can't encode character '\u23f0'`，导致 fallback 未执行。

## 影响
盘前/市场扫描在 AKShare 卡住或超时时无法自动降级，影响观察池候选生成和盘前建议稳定性。

## 复现步骤
1. 在 Windows 默认 GBK 输出环境运行 `scripts/scanner_with_fallback.py`。
2. 让主路径 `morning_scanner.py` 超时或抛出 `subprocess.TimeoutExpired`。
3. 观察 fallback 提示打印阶段是否崩溃。

## 期望结果
主路径超时或异常时，脚本应稳定打印提示并继续执行 `scanner_lite.py` 降级路径；不得因为日志字符编码导致流程中断。

## 回归标准
1. 模拟 `TimeoutExpired` 时 `try_primary()` 返回 `False`，不触发 `UnicodeEncodeError`。
2. 模拟主路径超时、降级路径成功时，`main()` 以退出码 0 完成。
3. 日志输出在 GBK/UTF-8 环境都不因 Emoji 或中文崩溃。

## 修复记录
2026-05-25：移除 scripts/scanner_with_fallback.py 控制台提示中的 Emoji，避免 Windows GBK stdout 编码失败；同时支持 SCANNER_PRIMARY_TIMEOUT 环境变量，便于回归测试快速模拟超时。
