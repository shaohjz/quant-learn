# Bug 管理

## Bug 状态定义
- `open` - 已提出，待研发处理
- `in_progress` - 研发修复中
- `fixed` - 研发已修复，待测试回归
- `verified` - 测试回归通过
- `reopened` - 回归失败，重新打开
- `won't fix` - 不修复

## 严重级别
- S0 阻塞：系统不可用/数据错误导致误导交易
- S1 严重：核心功能不可用
- S2 一般：功能异常但有绕过方式
- S3 轻微：体验/文案问题

## 流程
1. 测试发现问题 → 写 `pm/bugs/BUG-XXX.md`，状态 `open`
2. PM triage → 确认优先级/严重级别/是否阻塞发布
3. 研发修复 → 状态 `fixed`
4. 测试回归 → 通过改 `verified`，失败改 `reopened`
5. PM 汇报需求进度 + Bug 进度
