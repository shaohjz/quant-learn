# REQ-008: 每日PM自动状态扭转与新需求生成

## 背景
当前每日 PM 流程会扫描已有需求和日志，但没有强制执行“先完成状态扭转，再继续提出新需求”。导致已完成的 `testing` 需求和 `fixed` Bug 可能长期停留在中间状态，新需求也可能只复述上一轮内容。

## 目标用户/场景
用户希望每天自动推进 QuantLearn 仪表盘和量化系统：完成的需求要及时关闭，修好的 Bug 要及时回归，PM 还要根据当天日志持续提出新需求。

## 需求描述
每日研发闭环任务必须按顺序执行：
1. 扫描 `testing` 需求和 `fixed` Bug。
2. 根据测试报告/API检查结果做状态扭转：
   - 需求通过：`testing -> done`
   - Bug通过：`fixed -> verified`
   - 不通过：需求保持 `testing`，Bug 改 `reopened` 或新增 Bug。
3. 再读取当天日志、复盘、推送和用户反馈。
4. 如果发现新的产品机会，新增 1-3 个 `pending` 需求。
5. 每日报告必须明确列出：状态扭转项、新增需求、未解决阻塞。

## 数据来源
- `pm/requirements/*.md`
- `pm/bugs/*.md`
- `pm/test_reports/*.md`
- `docs/reviews/`
- `logs/`, `output/`, `reports/`
- `data/sim_live_mirror.db`
- 用户当天企微反馈摘要

## 验收标准
1. 每日闭环报告中必须包含“状态扭转”小节。
2. 已通过测试的 `testing` 需求会自动改为 `done`。
3. 已通过回归的 `fixed` Bug 会自动改为 `verified`。
4. 每天最多新增 3 个需求，且不得与已有需求重复。
5. 新需求状态必须为 `pending`。
