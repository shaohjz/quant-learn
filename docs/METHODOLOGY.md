# 交易策略改进方法论

> 这份文档回答一个问题：**每天复盘的时候，到底该改什么、不该改什么。**
> 执行工具是 `scripts/strategy_review.py`，每天 16:35 自动跑，产物在 `output/strategy_review/`。

---

## 0. 先承认一个事实

截至 2026-07-31，两个模拟账户的真实样本量是：

| 事实 | 数字 |
|------|-----:|
| 有台账的交易日 | 14 天 |
| 累计成交 | 57 笔 |
| #3 波段仓近 12 日成交 | **1 笔** |
| #3 连续 0 成交 | **8 天** |

在这个样本量下，统计学能告诉我们的东西少得可怜：

- 10 笔交易赢 6 笔，胜率的 95% 置信区间是 **[31%, 83%]** —— 和「不知道」几乎等价。
- 要证明 60% 的胜率真的强于抛硬币，需要约 **91 笔**已平仓交易。
- 按目前每月 ~10 笔的成交速度，攒到 91 笔要 **九个月**。

**结论：绝大多数「今天亏了，把止损从 5% 改成 4%」的操作，都是在拟合运气。**
改完之后下个月赚了，你不知道是不是因为这次改动；亏了，你也不知道该不该改回去。
一年下来参数转一圈回到原点，什么都没学到。

这不代表每天复盘没有意义 —— 而是**每天复盘的对象不该是参数**。

## 1. 分层：什么问题什么节奏

改动分三层，判定依据和样本门槛完全不同。这是整套方法论的核心。

| 层 | 节奏 | 问题长什么样 | 判定依据 | 样本门槛 | 允许动作 |
|----|------|-------------|---------|---------|---------|
| **执行层** | **每天** | 链路断了、参数自相矛盾、该买没买、两处定义对不上 | 逻辑与算术，**可当场证伪** | **不需要样本** | 直接改，当天改 |
| **信号层** | 每周 | 某类信号一直在亏、某个过滤器从没放行过 | 分信号的期望与胜率 | ≥ 20 笔/信号 | 提假设 + 影子对照 |
| **参数层** | 每月或攒够样本 | 止损太紧、止盈太早、仓位太重 | 整体胜率、盈亏比、回撤 | ≥ 50 笔 | 回测 → 影子 → 小额 → 放量 |

判断一个问题属于哪层，只问一句话：**换个月份、换只股票，这个结论还成立吗？**

- 「3 仓 × 1 万预算 = 3 万，本金 5 万，4 成资金永远用不到」→ 算术恒等式，永远成立 → **执行层**。
- 「这个月止损 5% 被打了 3 次」→ 换个月可能完全不同 → **参数层**，别急。

## 2. 每天只回答三个问题

这三个问题每天都有确定答案，不依赖样本量，所以适合日频。
`strategy_review.py` 就是围绕它们组织的。

### 问题一：链路今天完整跑完了吗？

看的是 `nav_stale` / `nav_missing` / `funnel` 这几类发现。
净值断更、台账没生成、池子没构建 —— 这些都是**故障**，不是策略问题。
故障期间的绩效数字全部不可信，当天复盘到此为止，先修链路。

### 问题二：规则说该做的，实际做了吗？

策略说「A/B 类信号 + 分数 ≥5 就买」，今天出了 3 个买点却 0 成交 —— 差在哪？

- 被仓位上限挡住 → 执行层，改口径
- 被现金不足挡住 → 执行层，改预算
- 信号根本没到阈值 → 正常，不是问题
- 没有任何记录 → **埋点缺失**，先补埋点，否则永远说不清

**「今天没成交」本身不是结论，「今天为什么没成交」才是。**

### 问题三：有人改了参数却没记录吗？

`unlogged_param_change`。每天给策略参数拍快照，和昨天比对。
参数变了但没有对应的假设 → P0。

理由在第 4 节。

## 3. 0 成交是最贵的成本

这条值得单列，因为它最容易被忽略。

#3 波段仓连续 8 天 0 成交，账面上「没亏钱」，看起来无害。但实际上：

- 8 天没有产生**任何**新样本
- 攒够 50 笔的时间被推迟了 8 天
- 策略好坏依然无从判断，下个月还是只能拍脑袋

**不成交的策略学不到东西。** 它既不赚钱，也不产生信息，是纯粹的时间损耗。

所以复盘时，「连续 0 成交」的优先级等同于「连续亏损」，两者都要开单处理。
如果确认是阈值过严导致的，宁可放宽到能出样本的程度先跑起来 ——
**先有反馈，再谈优化**。

## 4. 改动协议：先立赌约，再动手

任何策略参数改动，动手前必须在假设台账里登记：

```bash
python scripts/strategy_review.py --open-hypothesis \
  --param swing.max_positions --before 3 --after 5 \
  --layer parameter --horizon-days 21 --min-samples 20 \
  --expect "满仓拦截天数归零，月成交回到 8 笔以上"
```

四个字段缺一不可：

| 字段 | 作用 |
|------|------|
| `--param` | 改的是哪个旋钮，用来和参数快照的漂移比对 |
| `--expect` | **可证伪的预期**。写不出预期的改动不值得做 |
| `--horizon-days` | 多久之后复核，到期系统会提醒 |
| `--min-samples` | 样本不够时结论只能记 `inconclusive`，不许硬下判断 |

到期结案：

```bash
python scripts/strategy_review.py --close-hypothesis H-001 \
  --status confirmed|rejected|inconclusive --outcome "..."
```

**为什么强制这一步**：不写预期的改动，事后无法归因。
写了预期，无论结果是 confirmed 还是 rejected，都是一条净增的知识 ——
`rejected` 的价值不比 `confirmed` 低，它排除了一条错路。
这些结案记录累积起来，才是真正属于这个账户的方法论，而不是从书上抄来的通则。

**没登记就改参数会被抓**：每天的参数快照会比对出漂移，
找不到对应假设的改动直接报 P0。这条规则对人和对 LLM 一视同仁。

## 5. 证据等级：这个数字能不能信

`review/metrics.py` 给每个统计量标注等级，日报上直接显示。

| 已平仓笔数 | 等级 | 这个样本量能支持什么 |
|-----------|------|---------------------|
| 0 | 无数据 | 只能检查链路是否在跑 |
| 1–4 | 轶事 | 只能查执行 bug，不能推断策略好坏 |
| 5–19 | 弱 | 能看方向，不足以改参数 |
| 20–49 | 可用 | 可提改参提案，须先影子验证 |
| ≥ 50 | 较可靠 | 可走晋级流程 |

（上实盘另有更高门槛，见 `research/promotion_gate.py`，要求 ≥100 笔。）

配套的两个数字也要一起看：

- **保本胜率** = `1 / (1 + 盈亏比)`。5% 止损配 8% 止盈，盈亏比 1.6，保本胜率 38.5%。
  **先确认实际胜率有没有超过这条线，再讨论别的。**
- **还差多少样本** = 按当前胜率，要多少笔才能证明优势不是运气。这个数字通常大得让人清醒。

## 6. 反模式

以下操作在本项目里视为错误，复盘时发现要开单：

| 反模式 | 为什么错 |
|--------|---------|
| 今天亏了就调止损 | 单日样本量为 1，纯噪音 |
| 用未平仓浮盈算胜率 | 浮盈不是收益，只有平仓才算数 |
| 同一参数在两个文件各写一遍 | 改一处漏一处，盘中和收盘用不同规则 |
| 手写策略说明文档 | 必然漂移。说明书要从代码抽取生成 |
| 用兜底池期间的绩效评价选股能力 | 那几天的池子不是策略选的 |
| 「先观察一段时间」但不写观察什么 | 等于不观察。要写明指标、期限、样本门槛 |
| 样本不足时硬下结论 | 结论只能记 `inconclusive` |
| 回测跑赢就上生产 | 必须过 `research/promotion_gate.py` |

## 7. 一周的节奏

| 时间 | 做什么 | 依据 |
|------|--------|------|
| 每交易日 16:35 | `strategy_review.py` 自动跑，看执行层发现 | 本文第 2 节 |
| 每交易日 晚 | 执行层 P0/P1 当天修掉，改参数前先立假设 | 第 4 节 |
| 每周五 | 看信号层归因，样本够 20 笔的信号可以提假设 | 第 1 节 |
| 每月首个交易日 | 参数层复核：胜率 vs 保本胜率、回撤、到期假设结案 | 第 5 节 |
| 假设到期日 | 系统自动提醒，必须结案 | 第 4 节 |
